The input parameters for sedExnerFoam are numerous and are modifiable through different files in the current working directory. Some of the files are identical to other OpenFOAM solvers and won't be described in details herein. This is the case for the files:

system/blockMeshDict
system/controlDict
system/fvSchemes
system/fvSolution
constant/g
constant/dynamicMeshDict

The file 'blockMeshDict' contains the description of the base mesh (see Mesh generation, and createGeometry.py for cases that post-process the blockMesh points to set the initial bed shape). The file 'controlDict' contains the runtime parameters such as the timestep and the output interval. The file 'fvSchemes' describes the numerical schemes for the different differential operators (temporal, divergence, laplacian). The file 'fvSolution' describes the algebraic solvers, the associated tolerances, and the PIMPLE algorithm controls, including the sedExnerFoam-specific sub-iteration keywords described in PIMPLE sub-dictionary: sub-iteration controls below. The file 'g' contains the gravity vector. The file 'dynamicMeshDict' configures the ALE mesh motion solver used to deform the mesh so that the bed boundary follows the Exner equation (see Arbitrary Lagrangian Eulerian (ALE) Approach in Governing equations); the patches listed under 'sedimentBedPatches' (see Bed existence and motion below) must be declared as moving boundaries there.

The files that contain the specific input parameters for sedExnerFoam are:

constant/transportProperties
constant/suspensionProperties
constant/bedloadProperties

If the sub-dictionary 'wallDiffusivity' is absent, this correction is disabled.

File bedloadProperties

This dictionary configures the sediment bed itself (instantiating a sedimentBed object, see sedimentBed.C) as well as the bedload transport and Exner equation models.

Bed existence and motion

parameterdescriptionrequireddefault
sedimentBedswitch on/off the sediment bed entirely (finite area mesh, bedload, Exner equation)yes- (on/off)
sedimentBedPatcheslist of mesh patch names forming the sediment bed (used to build the finite area mesh); must be consistent with the moving patches declared in dynamicMeshDictyes, if sedimentBed=on-
bedMotionon: the bed moves (Exner equation deforms the mesh); off: bedload/Shields are still computed but the bed does not movenoon
rigidBedon: a non-erodible layer limits erosion/bedload where the sediment layer thickness vanishes (see HsedBed field, rigidBed treatment in bedload.H, CsEqn.H, balanceBedload.H)nooff

If sedimentBed=on, the gravity vector must point into the bed (consistency check performed at startup: g & faceAreaNormals > 0 on every bed face, otherwise a FatalError is raised).

Bedload saturation (sub-dictionary 'saturation')

parameterdescriptionrequired (if saturation present)default
typesaturation modelnoexplicit
Tsatsaturation timeyes, unless type=none- (s)
Lsatsaturation lengthyes, unless type=none- (m)

Valid values for 'type': implicit1D, explicit, semiImplicit, none (see bedload.H). If the 'saturation' sub-dictionary is absent entirely, no saturation length/time is used (qb = qsat directly, equivalent to type=none).

Bedload flux scheme (sub-dictionary 'exnerAdvection')

parameterdescriptiondefault
qbSchemeinterpolation scheme for the shear-stress bedload flux on faMesh edges (centered or upwind)upwind
qavSchemeinterpolation scheme for the avalanche bedload flux on faMesh edges (centered or upwind)centered

If the 'exnerAdvection' sub-dictionary is absent, the defaults above apply.

Sub-dictionary 'bedloadModel'

parameterdescriptiondefault
typebedload transport model (see bedloadModels)MeyerPeter
onEdgecompute the avalanche bedload flux directly on faMesh edges instead of on facesoff

If the 'bedloadModel' sub-dictionary is absent, type=MeyerPeter is used with onEdge=off.

Sub-dictionary 'criticalShieldsModel'

parameterdescriptiondefault
typecritical Shields number model (see criticalShieldsModels); the special value 'readFromFile' reads a user-provided non-uniform critShields field from <time>/finite-area/critShields instead of computing it, and disables the slope correction in bedload.HfixedValue
valueconstant critical Shields number (only used when type=fixedValue)0.047

If the 'criticalShieldsModel' sub-dictionary is absent, type=fixedValue with value=0.047 is used.

PIMPLE sub-dictionary: sub-iteration controls

These keywords are read directly from the PIMPLE sub-dictionary of system/fvSolution (not from bedloadProperties):

parameterdescriptiondefault
nOuterCorrectorsstandard PIMPLE keyword; nOuterCorrectors > 1 activates the PIMPLE-Exner sub-iteration (see PIMPLE-Exner Sub-Iterations in Governing equations)1
moveMeshOuterCorrectorsstandard PIMPLE keyword; must be 'yes' for the bed to actually move at every sub-iteration, otherwise only the first outer iteration updates the mesh and a warning is printed at the start of the run-
zbRelaxunder-relaxation factor applied to the bed level increment dH across sub-iterations, in ]0, 1]1.0
zbTolconvergence tolerance (in m) on max|dH - dH_prev| between sub-iterations, used only for reporting (not to stop the loop early)1e-6

With nOuterCorrectors = 1, the behaviour is unchanged from a version without the sub-iteration feature.
